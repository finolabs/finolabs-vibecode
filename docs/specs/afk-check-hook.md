# afk check hook

Status: implemented; rule recorded as the tenth scoped exception in `CLAUDE.md` (owner decisions, 17/11/2026); `scripts/afk_check_hook.py`, tests in `tests/test_afk_check_hook.py`; live host delivery unverified.

## Why

Under an away lease, `afk/references/lease-rules.md` asks the agent to run `afk.py check` before every action. That is advisory (agent judgment): one skipped call and the credential floor, the only limit `open` keeps, does not apply, and every action costs a second tool call. The pack review of 17/11/2026 (C10, A1) named a host-run check as the way to close that gap and placed it under "too risky for 0.3.2, defer"; owner decision 1 below overrides that placement.

## Owner decisions (17/11/2026)

1. Ship it in 0.3.2.
2. Deny every Tier 3 answer, in both modes ("the most automated direction"): the hook replaces the agent's own `check` call for Bash on Claude Code.
3. A command that cannot be split into words is denied (the floor comes first), with a fixed message asking for a simpler command.

The review of this rule (PR 336) made the hook fail closed once a lease is live, as `check` does, in line with decision 3.

## Behavior

- One `PreToolUse` hook, matcher `Bash`, in its own group of the Claude Code manifest with `"timeout": 15`; never in the metrics group.
- Off unless a valid, unexpired away lease exists under the canonical data root; `FNL_AFK_HOOK=off` turns it off. No lease, an expired, stopped or unreadable lease, and any error before the lease is established allow with no output.
- Reads `tool_input.command` and `cwd` from at most 256 KiB of hook input; input at that cap allows with no lease and denies as `unsafe` under a live lease. A backslash-newline outside single quotes (in double quotes too) is removed, joining the lines as bash does; an escaped backslash (`\\`) is not a continuation, so the newline after it still separates; any other newline outside quotes and comments becomes a ` ; ` separator (a `#` that starts a word comments to the end of the line); a `$"..."` locale string outside quotes is read as `"..."`; a `$'...'` string with no backslash is read as `'...'`, and one holding a backslash makes the command unreadable (the split message), since its escapes would hide a name or path; then `shlex.split` (POSIX mode, no comments) gives the argv. A heredoc body is therefore judged line by line: a false denial is possible, a missed floor command is not.
- Before judging, the raw command is scanned with the same quote tracking (single-quoted text is literal), and the hook denies with the split message any form it cannot reproduce exactly in bash or zsh (the Bash tool may run either): brace expansion (`{a,b}`, `{a..b}`); a `${...}` other than `${name}`; any `$name` or `${name}` other than `$HOME` or `${HOME}` followed by `/`, whitespace, the end or (in double quotes) a closing quote and then one of those, since an unset variable, one set earlier in the command, a variable only the Bash tool's environment holds and zsh modifiers (`$X:t`) or subscripts (`$X[1]`) all expand where the hook cannot follow; a special or positional parameter (`$_ $@ $* $# $? $- $$ $! $0`-`$9`); `$((` and `$[`; `<(` and `>(`; an operator outside quotes glued to a word (`git commit -m x;printenv`, `a&&b`, `ls|cat`), found by comparing the operators a punctuation-aware split sees with those standing alone, since a text value such as a commit message would otherwise swallow the command after it; a command substitution (`$(...)` or a backtick), whose output exists only at run time (a commit message goes through `-F <file>` instead); a glob not anchored at `/` or `~` in a command holding `cd`, `pushd`, `popd` or `chdir` (a leading `(`, `{` or `!` stripped, so a subshell or group counts), which the shell expands in a folder the hook cannot know; a program fed by run-time data, whose command or files exist only at run time: `xargs` anywhere, `find` with `-exec`, `-execdir`, `-ok`, `-okdir` or `-delete`, and `fd`/`fdfind` with `-x`, `-X` or `--exec...` (owner decision 17/11/2026: a syntax allowlist; the hook reads only what it can reproduce in full and every form outside it gets the split message, so a false denial is expected); a word starting with `=` (zsh); a `(` inside a word (zsh glob alternation and qualifiers); a `~+`, `~-` or `~N` prefix. For every command `afk.py`'s `commands_of` reads out of the argv over all of its `READINGS` (so an operator glued to a word, a compound word such as `if`, `then` or `!`, leading `NAME=value` words and the common wrappers are resolved; `commands_of` reads wrapper flags with one shared table, so a flag can hide the next word; the wrapper-flag rule below denies that), and for the argv after a `find` `-exec`, `-execdir`, `-ok` or `-okdir`, read through the same steps, a program name holding `$`, a backtick, a glob or a brace, `eval`, `source`, `.`, or a shell (`sh`, `bash`, `zsh`, `dash`, `ksh`, `mksh`, `fish`, `csh`, `tcsh`) given `-c`, `-s`, `<<<`, `<` or nothing but options (so it would read code from stdin or a pipe), or a change of the shell's globbing options (`setopt`, `unsetopt`, `shopt`, `emulate`, or `set` with any word naming a glob, magic, equals, brace, rcexpand or wordsplit option, glued forms such as `-oextendedglob` included) also gets the split message. So does any argv word equal to `builtin`, `nocorrect`, `hash`, `alias`, `function`, `case`, `coproc`, `enable`, `unalias`, `trap` (which runs a string as code), `watch` or `parallel`, and, after any wrapper of `afk.py`'s `PREFIX_WORDS` (read once every operator glued to a word, such as `ls|xargs`, `(xargs` or `true&&xargs`, is cut out), any flag outside its short allowlist (`timeout -k -s`, `nice -n`, `exec -a -c -l`, `npx -y --yes -p`, each valued one with its value; every other wrapper allows none), and any flag within the three words after `flock` or `script`, since the shared flag table may misread it (`caffeinate -s`, `stdbuf -oL`, `command -p`, `sudo -n`, `xargs -J`, `npx --package`, `uvx --from`, `timeout --kill-after`, `flock f -c`). Wrappers are not trusted to hide a name: any argv word that is not a git, gh or glab text value, and any expanded path, whose base name is a credential command `afk.py` floors in every use (`CREDENTIAL_COMMANDS` entries with no subcommand list, such as `printenv` or `security`), or is a credential command with subcommands followed anywhere later in the argv by one of them (`gh` then `auth`, `docker` then `login`; an expanded program path counts wherever it stands), or starts a `CREDENTIAL_PAIRS` entry whose words follow in order (`kubectl get secret`, `az account get-access-token`), denies with `floor`. A false denial is possible; the agent rewrites the command directly.
- This install's own `afk.py` (the resolved path of `skills/delegate/scripts/afk.py` beside the hook) run as `python3 [-I] <path> <sub>` with `<sub>` one of `stop`, `log`, `review`, `effective`, `rules`, `check`, `packet-check`, nothing after an operator and every argument made only of letters, digits, spaces and `._,:=/@+%-` (so no word can carry an expansion, a redirection or a `;`, `|`, `&`, `(` or `)` that bash would split on), is allowed without judgment, so `/afk stop`, Decide records and reviews keep working in `strict`.
- Every other argv goes to the same `afk.py main(['check', '--coordinator', 'claude', '--argv-json', ...])`, run in `cwd`. A missing `cwd`, or one that is not a directory, denies with `unsafe`.
- Each word, and each piece of a word split at whitespace, `<`, `>`, `|`, `&`, `;`, `(` and `)` (so a multi-line word or a glued redirect cannot hide one), holding `~`, `$` or a glob character (`*`, `?`, `[`) is also expanded in memory (`os.path.expanduser`, then `$name` and `${name}` from the hook's environment with an unset variable expanding to nothing as in the shell, then `glob`; a recursive `**` glob, which zsh also matches with no folder, and a word with more than 200 matches get the split message, never a truncated reading), and the floor-by-name rule also reads the argv with the same expansion; when `afk.py`'s floor reads any match as a floor path, or the argv with `~` and variables expanded touches the floor, the hook denies with `floor`. Expanded values and paths are never stored, logged or printed.
- Tier 1 answer: print nothing, return no decision, so the user's own permission rules still apply (never `permissionDecision: allow`). Tier 3 answer: deny with `afk: <code>; this action is parked under the away lease (afk.py check)`. A split error: deny with `afk: the command could not be read; write it as a simpler command`. Any error once the lease is live, and the hook's own 12-second alarm: deny with `afk: unsafe; ...` (the same message form).
- Side effects are exactly those of a `check` call: counters, limits, merge pins and the approval-used record, in the private state folder.
- `lease-rules.md` on Claude Code: the agent does not run its own `check` before a Bash command and does not use `check ... && <command>` there (the hook judges the command; a second check would double the counters and spend a one-time approval). `check --paths` before an edit-tool change, and every check on Codex, stay the agent's (advisory, agent judgment).

## Not covered

Codex and Antigravity (no equivalent hook wired here); a Bash call that reaches the same work through another tool; a string a program hands to a shell itself (`git rebase --exec`, a `git -c alias.x='!...'`), which `afk.py`'s own command corpus judges; code inside a script file the check allowed (`bash scripts/x.sh` runs, and its content is not read); a bare `python3` in the lease-command exemption, which the Bash tool resolves through its own `PATH`; and a `$NAME` inside a quoted heredoc, which the shell leaves literal but the hook denies (a false denial). A `$HOME` that the Bash tool's environment sets differently from the hook's is expanded from the hook's. The hook reads the shell with its default options: a profile or shell snapshot that turns on zsh `extendedglob` (where `#`, `^` and `~` inside a word are glob operators) or `autocd` at top level is outside what it reads.

## Verification

Tests in `tests/test_afk_check_hook.py`, each through the real script under a real `afk start` lease in a synthetic home:

- no lease allows; a stopped lease and `FNL_AFK_HOOK=off` allow; other tools and bad input allow; input past the cap denies as `unsafe` under a live lease; `gh au${UNSET}th token`, `cat ~/.net"$NOPE"rc`, `X=auth; gh $X token`, `gh $SHELL:t:s/zsh/auth/ token` and `cat $HOME[1]` get the split message while `cat $HOME/.netrc` floors; the lease-command exemption needs a bare `python3`/`python` or the hook's own interpreter; `gh $(echo au)th token`, a backtick, `cd ~ && cat .ne?rc`, `pushd ~; cat .ne*c`, `chdir ~ && cat .ne?rc`, `(cd ~ && cat .ne?rc)`, `echo auth token | xargs gh`, `xargs -0 -n 1 ls`, `find ~ -name '.ne*c' -exec cat {} +`, `find . -name x -delete` and `fd netrc ~ -x cat`, `git commit -m x;printenv`, `echo ok&&printenv`, `cat ~/**/.ne?rc` and a glob past 200 matches get the split message, while `git status -- "a;b"` is read and resolves the script against the Bash tool's `cwd`;
- open: `printenv`, `echo ok && env`, `ls` then `printenv` on the next line, a heredoc followed by `printenv`, and `cat ~/.n?trc` (with a synthetic `.netrc`) deny with `floor`; `git status` and a multi-line quoted commit message are silent;
- strict: an unknown command denies with `unknown`; `afk.py stop`, `afk.py log ...` and `afk.py check ...` of this install are silent; `cd x && git status` follows `check`;
- an own `afk.py` lease command with `$(...)`, a backtick, a redirect, `x;printenv` or `x|cat ~/.netrc` in an argument is judged and denies with `floor`;
- a `#'` comment followed by `cat ~/.n?trc` on the next line, `cat ~/.ne\` + newline + `trc`, the same inside double quotes, and `$"printenv"` deny with `floor`; `echo a\\` + newline + `printenv` denies with `floor` (no continuation); `$'\x70rintenv'` denies with the split message;
- `/usr/bin/printen?`, `{printenv,}`, `cat ~/.ne{t,}rc`, `${x:-printenv}`, `>(printenv)`, `<(cat ~/.ne?rc)`, `"$@"`, `$_`, `$(( 1 ))`, `=printenv`, `~/.(netrc|x)`, `~+/.netrc`, `eval`, `bash -c`, `sh <<<`, `| sh`, `$x` as a command, `echo x|/usr/bin/printen?`, `if true; then /usr/bin/printen?; fi`, `env` or `timeout 5` before `/usr/bin/printen?`, `env bash -c ...`, `command eval x`, `find . -exec /usr/bin/printen? \;`, `find . -exec sh -c ... \;`, `setopt extendedglob`, `set -o extendedglob`, `set -oextendedglob`, `builtin eval x`, `nocorrect ls`, `case ... esac`, `function f { ...; }`, `hash -p ...`, `command -p ls`, `time -p ls`, `sudo -n ls` and `find . -exec timeout 5 sh -c x \;` deny with the split message; `env -i printenv`, `nice printenv`, `nohup kubectl get secret x`, `xargs az account get-access-token` and `nohup gh auth token` deny with `floor`; `caffeinate -s sh -c ...`, `caffeinate -s kubectl get secret x`, `caffeinate -t 5 gh auth token`, `stdbuf -oL ls`, `caffeinate -s docker login`, `xargs -J % sh -c x`, `xargs -n 1 -E x sh -c x`, `npx --package x sh -c x`, `uvx --from x sh -c x`, `flock f -c x` and `timeout --kill-after 1 5 sh -c x` deny, and so do the glued forms `ls|xargs -J % sh -c x`, `true&&xargs -J % sh -c x`, `(xargs -J % sh -c x)`, `ls;flock f -c x`, `ls|sudo -n sh -c x` and `(nice -5 sh -c x)`; `trap 'ls' EXIT` denies with the split message; `git status`, `"${HOME}"`, `bash scripts/run.sh`, `python3 -c ...`, `set -e`, `set -euo pipefail`, `env FOO=1 ls`, `env -i ls`, `timeout 5 ls` and `npx -y prettier --check .` do not get the split message (`env -i ls` floors instead: `env` with options is read as the command `env`, which prints the environment); `cat x<~/.n?trc` denies with `floor`;
- an unbalanced quote denies with the split message; a non-directory `cwd` denies with `unsafe`; a classifier error under a live lease denies with `unsafe`;
- the command text and an expanded path appear in no file the test can read afterwards; a merge command writes the same merge pin a `check` call writes; the manifest holds the hook in its own group with its timeout.
