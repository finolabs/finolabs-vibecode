# afk check hook

Status: implemented; rule recorded as the tenth scoped exception in `CLAUDE.md` (owner decisions, 17/11/2026; its tokenizer by owner decisions of 18/11/2026, [afk-hook-tokenizer.md](afk-hook-tokenizer.md)); `scripts/afk_check_hook.py`, tests in `tests/test_afk_check_hook.py`, `tests/test_afk_commands.py` and `tests/test_afk_hook_oracle.py`; live host delivery unverified.

## Why

Under an away lease, `afk/references/lease-rules.md` asks the agent to run `afk.py check` before every action. That is advisory (agent judgment): one skipped call and the credential floor, the only limit `open` keeps, does not apply, and every action costs a second tool call. The pack review of 17/11/2026 (C10, A1) named a host-run check as the way to close that gap and placed it under "too risky for 0.3.2, defer"; owner decision 1 below overrides that placement.

## Owner decisions (17/11/2026)

1. Ship it in 0.3.2.
2. Deny every Tier 3 answer, in both modes ("the most automated direction"): the hook replaces the agent's own `check` call for Bash on Claude Code.
3. A command that cannot be split into words is denied (the floor comes first), with a fixed message asking for a simpler command.

The review of this rule (PR 336) made the hook fail closed once a lease is live, as `check` does, in line with decision 3.

## Behavior

- One `PreToolUse` hook, matcher `Bash`, in its own group of the Claude Code manifest with `"timeout": 15`; never in the metrics group.
- Off unless a valid, unexpired away lease exists under the canonical data root; `FNL_AFK_HOOK=off` turns it off. No lease, an expired, stopped or unreadable lease, and any error before the lease is established allow with no output.
- Reads `tool_input.command` and `cwd` from at most 256 KiB of hook input; input at that cap allows with no lease and denies as `unsafe` under a live lease.
- **Tokenizer** ([afk-hook-tokenizer.md](afk-hook-tokenizer.md) A). One pass over the raw text that keeps the quoting of every character (unquoted, single, double, escaped) emits the call's command sites. Each site holds its leading `NAME=value` assignments, its argv (quotes removed) and its redirects (fd, operator, target), and is marked when a pipe feeds it, when its output feeds a pipe and when it sits anywhere in a loop, its condition included (`repeated`). The grammar is what bash and zsh, with default options, both read the same way:
  - words: unquoted text, `'...'`, `"..."`, a backslash outside quotes, a backslash-newline outside single quotes joining the lines (an escaped backslash, `\\`, is no continuation), and a `$'...'` string with no backslash read as `'...'`;
  - control operators `;`, `&&`, `||`, `|`, `&` and newline, and redirects `<`, `>`, `>>`, `>|`, `<>`, `<&`, `>&`, `&>`, `<<`, `<<-` and `<<<`, recognized only outside quotes by longest match. An operator glued to a word (`ls /tmp;git status`, `printenv>&2`, `cat<f`) is read as bash reads it, and a quoted or escaped one (`'a;'`, `a\;`) stays in its word;
  - a fd number only as one unquoted digit that starts a word and is glued to its redirect (`printf x2>out` has no fd);
  - a `#` comment only at the start of a word (`echo x\ #` is one word, `x #`);
  - heredoc bodies, read to their delimiter line with the delimiter's quoting;
  - the compound forms `if ... fi`, `while` and `until ... do ... done`, `for NAME in words; do ... done`, `( ... )` and `{ ...; }`, whose reserved words count only unquoted in command position; the `for` list words are data the floor reads.
- **Split message.** The hook denies with the split message every form outside that grammar, and every form the syntax allowlist (owner decision 17/11/2026) leaves out, checked per character with the quoting known: an unbalanced quote; a heredoc with no closing delimiter; a `$'...'` string holding a backslash, whose escapes would hide a name or path; a `$"..."` string, which bash and zsh expand differently; `|&` (a syntax error in bash 3.2), `&>>`, zsh's `&|`, `&!`, `>!`, `>>!`, `>&|`, `>>|` and `&>|`; two or more digits glued to a redirect (`12>&1`: bash reads a fd, zsh an argument); a zsh numeric glob (`<1-3>`) and a named fd (`{x}>`); `case`, `select`, `function`, `coproc`, `repeat`, `foreach`, `[[ ]]`, `for ((`, `for NAME` with no `in` and the zsh short forms; a redirect on a compound command; and, outside single quotes: brace expansion (`{a,b}`, `{a..b}`); a `${...}` other than `${HOME}`; any `$name` or `${name}` other than `$HOME` or `${HOME}` followed by `/` or the end of its word, since an unset variable, one set earlier in the command, a variable only the Bash tool's environment holds and zsh modifiers (`$X:t`) or subscripts (`$X[1]`) all expand where the hook cannot follow; a special or positional parameter (`$_ $@ $* $# $? $- $$ $! $0`-`$9`) and zsh's `$^x`, `$=x`, `$~x`, `$+x`; `$((` and `$[`; `<(` and `>(`; a command substitution (`$(...)` or a backtick), whose output exists only at run time (a commit message goes through `-F <file>` or a heredoc to `git commit -F -` instead); a word starting with `=` (zsh); a `(` inside a word (zsh glob alternation and qualifiers, an array); a `~+`, `~-` or `~N` prefix, or a quoted character in a tilde prefix. The variable and substitution rules apply inside a heredoc body whose delimiter is unquoted, since the shell expands it.
- **Per site.** For every site, and for every command `afk.py`'s `commands_of` reads out of it over all of its `READINGS` (leading `NAME=value` words, the common wrappers, inline code and the argv after a `find` `-exec`, `-execdir`, `-ok` or `-okdir` included), the split message also follows from: a program name holding `$`, a backtick, a glob or a brace; `eval`, `source`, `.`; a shell (`sh`, `bash`, `zsh`, `dash`, `ksh`, `mksh`, `fish`, `csh`, `tcsh`) given `-c`, `-s` or no script operand (`-o` and `-O` take a value), so it would read code from stdin or a pipe, whatever its redirects are (`sh>out`, `sh <file`); a change of the shell's globbing options (`setopt`, `unsetopt`, `shopt`, `emulate`, or `set` with any word naming a glob, magic, equals, brace, rcexpand or wordsplit option, glued forms such as `-oextendedglob` included); a program fed by run-time data (`xargs`, `find` with `-exec`, `-execdir`, `-ok`, `-okdir` or `-delete`, `fd`/`fdfind` with `-x`, `-X` or `--exec...`); any word of the site equal to `builtin`, `nocorrect`, `hash`, `alias`, `function`, `case`, `coproc`, `enable`, `unalias`, `trap` (which runs a string as code), `watch` or `parallel`; and, for a wrapper of `afk.py`'s `PREFIX_WORDS` in command position (the site's program, then the program each wrapper runs, past `env`'s assignments and `pnpm exec`), any flag outside its short allowlist (`timeout -k -s`, `nice -n`, `exec -a -c -l`, `npx -y --yes -p`, each valued one with its value; every other wrapper allows none), and any flag within the three words after `flock` or `script`, since the shared flag table may misread it (`caffeinate -s`, `stdbuf -oL`, `command -p`, `sudo -n`, `npx --package`, `uvx --from`, `timeout --kill-after`, `flock f -c`). The words after the program that runs are its own arguments: `codex exec -s read-only` is Codex's subcommand, not the shell's `exec`, in every placement.
- **Call-wide rules** (tokenizer spec B), over every site, nested groups and redirect targets included: a directory change (`cd`, `pushd`, `popd`, `chdir`) anywhere in the call together with an unquoted glob not anchored at `/` or `~` anywhere in the call (`cd ~ && cat .ne?rc`), which the shell expands in a folder the hook cannot know; a pipe into a shell, `xargs` or a code reader (a program of `afk.py`'s `INTERPRETERS` and `INLINE_FLAGS` tables, `python3.12` and the like included), whatever feeds the pipe, so `cat <<'EOF' | node` stays denied; a `<` file feeding a code reader, whose content the hook does not read.
- **Heredoc, `<<<` and their bodies** (decision 3). A body is data only when its receiver, with no wrapper, is on a closed list of data readers (`cat`, `tee`, `wc`, `head`, `tail`, `sort`, `grep`, `git commit -F -`, `git tag -F -`, `gh ... --body-file -`), every program downstream of it through pipes is on the same list, and no subshell or group takes part in that pipeline. A data body's words go through the floor-by-name and floor-by-path rules (expanded with `$HOME` when its delimiter is unquoted). Every other body (a shell, `node`, `python*`, an unknown program, a wrapper) is read line by line as commands with the same tokenizer, and its sites are judged like the call's own, so `node <<'EOF'` with `console.log(process.env)` stays denied.
- **Floor.** For each site, each word, and each piece of a word split at whitespace, `<`, `>`, `|`, `&`, `;`, `(` and `)`, holding `~`, `$` or a glob character is expanded in memory (`os.path.expanduser`, then `$HOME` from the hook's environment, then `glob`; a recursive `**` glob, which zsh also matches with no folder, and a word with more than 200 matches get the split message, never a truncated reading). Each redirect target that names a file (fd duplications such as `2>&1` left out) is expanded the same way, its unquoted `~` and `$HOME` only; a target glob that matches more than one file gets the split message (bash refuses it, zsh opens every match). When `afk.py`'s floor reads any match or target as a floor path, or the site's argv with `~` and `$HOME` expanded touches the floor, the hook denies with `floor`. Wrappers are not trusted to hide a name: any word of a site that is not a git, gh or glab text value, and any expanded path or redirect target, whose base name is a credential command `afk.py` floors in every use (`CREDENTIAL_COMMANDS` entries with no subcommand list, such as `printenv` or `security`), or is a credential command with subcommands followed anywhere later in the site by one of them (`gh` then `auth`, `docker` then `login`; an expanded program path counts wherever it stands), or starts a `CREDENTIAL_PAIRS` entry whose words follow in order (`kubectl get secret`, `az account get-access-token`), denies with `floor`. One narrow exception (decision 7): a file operand of a data reader that executes nothing (`cat`, `head`, `tail`, `wc`, `grep`, `ls`, `stat`, `file`, `sort` as the site's program, with no assignment) skips the every-use base-name rule, not its option values and not the pattern of `grep`, so `cat .local-ci/x/pass` is read while `python3 /tmp/pass` and `node --require /tmp/pass -e 0` floor; the floor-by-path rule still applies to every operand. Expanded values and paths are never stored, logged or printed.
- This install's own `afk.py` (the resolved path of `skills/delegate/scripts/afk.py` beside the hook) run as `python3 [-I] <path> <sub>` with `<sub>` one of `stop`, `log`, `review`, `effective`, `rules`, `check`, `packet-check`, as the call's only site with no assignments and no redirects, and every argument made only of letters, digits, spaces and `._,:=/@+%-` (so no word can carry an expansion, a redirection or a `;`, `|`, `&`, `(` or `)` that bash would split on), is allowed without judgment, so `/afk stop`, Decide records and reviews keep working in `strict`. It never exempts a sibling site.
- Every other call goes to the same `afk.py main(['check', '--coordinator', 'claude', '--commands-json', ...])`, run in `cwd`, as a list of `{assignments, argv, redirects, repeated}` with each redirect as its kind (read, write, append, read-write) and expanded target. A missing `cwd`, or one that is not a directory, denies with `unsafe`. `check` judges each site exactly as `--argv-json` judges its assignments and argv, and each site's redirect targets as `--paths` judges them (the floor in either mode and, in `strict`, the path permission, reads included, so `git status > AGENTS.afk.md` and `git status < /tmp/input` deny in `strict`; in `open` the ninth exception leaves `AGENTS.afk.md` unprotected and a target needs only the floor). A site with only redirects is judged by its targets in `open` and is `unknown` in `strict`. `--argv-json` stays unchanged for the agent's own checks on Codex and Antigravity.
- **Recording** (decision 2). Every site is judged before anything is recorded; any denial denies the call and records nothing (no counter, merge pin or approval use). A call that passes is recorded once: the action counter once, one run reservation per run-reserving site (a ledger start), one merge pin per merge site, and an approval used only by the one site whose exact subject it names, so two sites that need the same one-time approval deny the second. A site in a loop that would use an approval, reserve a run or merge denies (`unknown`), since its count is unknown before it runs. The call's summed run reservations must fit `Max runs`, else the call denies with `spent` before any is kept.
- Tier 1 answer: print nothing, return no decision, so the user's own permission rules still apply (never `permissionDecision: allow`). Tier 3 answer: deny with `afk: <code>; this action is parked under the away lease (afk.py check)`. A split error: deny with `afk: the command could not be read; write it as a simpler command`. Any error once the lease is live, and the hook's own 12-second alarm: deny with `afk: unsafe; ...` (the same message form).
- Side effects are exactly those of `check` calls: counters, limits, merge pins and the approval-used record, in the private state folder.
- `lease-rules.md` on Claude Code: the agent does not run its own `check` before a Bash command and does not use `check ... && <command>` there (the hook judges the command; a second check would double the counters and spend a one-time approval). `check --paths` before an edit-tool change, and every check on Codex, stay the agent's (advisory, agent judgment).

## Not covered

Codex and Antigravity (no equivalent hook wired here); a Bash call that reaches the same work through another tool; a string a program hands to a shell itself (`git rebase --exec`, a `git -c alias.x='!...'`), which `afk.py`'s own command corpus judges; code inside a script file the check allowed (`bash scripts/x.sh` runs, and its content is not read), an interpreter fed a script file (`node x.js`) and the content of a `<` file, which the hook never reads; a bare `python3` in the lease-command exemption, which the Bash tool resolves through its own `PATH`; and a variable other than `$HOME`, which the hook denies even where the shell would leave it literal (a quoted heredoc body is data, but a line-by-line body is read as commands; a false denial). A `$HOME` that the Bash tool's environment sets differently from the hook's is expanded from the hook's. The hook reads the shell with its default options: a profile or shell snapshot that turns on zsh `extendedglob` (where `#`, `^` and `~` inside a word are glob operators) or `autocd` at top level is outside what it reads. A variable assigned earlier in the same call (decision 6 of the tokenizer spec) is a later step and still gets the split message.

## Verification

Tests in `tests/test_afk_check_hook.py`, each through the real script under a real `afk start` lease in a synthetic home:

- no lease allows; a stopped lease and `FNL_AFK_HOOK=off` allow; other tools and bad input allow; input past the cap denies as `unsafe` under a live lease; `gh au${UNSET}th token`, `cat ~/.net"$NOPE"rc`, `X=auth; gh $X token`, `gh $SHELL:t:s/zsh/auth/ token` and `cat $HOME[1]` get the split message while `cat $HOME/.netrc` floors; the lease-command exemption needs a bare `python3`/`python` or the hook's own interpreter; `gh $(echo au)th token`, a backtick, `cd ~ && cat .ne?rc`, `pushd ~; cat .ne*c`, `chdir ~ && cat .ne?rc`, `(cd ~ && cat .ne?rc)`, `echo auth token | xargs gh`, `xargs -0 -n 1 ls`, `find ~ -name '.ne*c' -exec cat {} +`, `find . -name x -delete` and `fd netrc ~ -x cat`, `cat ~/**/.ne?rc` and a glob past 200 matches get the split message, while `git status -- "a;b"` is read; `git commit -m x;printenv`, `git commit -m x;(printenv)` and `echo ok&&printenv` floor, the glued operator read as bash reads it;
- open: `printenv`, `echo ok && env`, `ls` then `printenv` on the next line, a heredoc followed by `printenv`, and `cat ~/.n?trc` (with a synthetic `.netrc`) deny with `floor`; `git status` and a multi-line quoted commit message are silent;
- strict: an unknown command denies with `unknown`; `afk.py stop`, `afk.py log ...` and `afk.py check ...` of this install are silent;
- an own `afk.py` lease command with `$(...)` or a backtick in an argument gets the split message, and one with a redirect, `x;printenv` or `x|cat ~/.netrc` is judged and denies with `floor`;
- a `#'` comment followed by `cat ~/.n?trc` on the next line, `cat ~/.ne\` + newline + `trc` and the same inside double quotes deny with `floor`; `echo a\\` + newline + `printenv` denies with `floor` (no continuation); `$'\x70rintenv'` and `$"printenv"` deny with the split message;
- the shell forms of the allowlist (`/usr/bin/printen?`, `{printenv,}`, `${x:-printenv}`, `>(printenv)`, `"$@"`, `$(( 1 ))`, `=printenv`, `~/.(netrc|x)`, `~+/.netrc`, `eval`, `bash -c`, `sh <<<`, `| sh`, `setopt extendedglob`, `case ... esac`, `function f { ...; }`, the wrapper flags and their glued forms) deny with the split message; `env -i printenv`, `nice printenv`, `nohup kubectl get secret x` and `nohup gh auth token` deny with `floor`; `exec -x ls` through a wrapper, a redirect or a quoted `;` gets the split message, while `codex exec` in any placement, `cd x && codex exec ...` included, is Codex's subcommand;
- the tokenizer spec's cases: `ls /tmp; git status`, `ls /tmp ; pwd ""`, `git status 2>&1 | head`, `grep -E "a|b" f`, `codex exec -s read-only x`, a heredoc commit message holding `;` fed to `git commit -F -` and `cat .local-ci/x/pass` are silent; `gh pr create --body; env`, `printenv>&2`, `cat<.netrc`, `gh>out auth token`, `echo x\ #; env`, `python3 /tmp/pass` and `node --require /tmp/pass -e 0` floor; `git commit -m; env`, `true; 2>&1 env` and `node <<'EOF'` with `process.env` deny; `printf x | sh>out`, `$"abc"`, `printf x 12>&1`, `cat <<'EOF' | node`, `cat <<'EOF' | tclsh`, `sh <in`, `node <script.js`, `S=README; for S in auth; do :; done; gh $S token`, `(S=README); cat $S` and `false && S=README; cat $S` get the split message; the assignment guard `GIT_CONFIG_COUNT=1 ... git push origin` denies with `guarded`; in `strict`, `git status > AGENTS.afk.md` denies with `protected` and `git status < /tmp/input` with `unknown`, and in `open` the first is silent; with one outstanding approval, `for x in a b; do make task; done`, `while make task; do git status; done` and `make task; make task` deny while `git status && make task` uses it once; two ledger starts in one call deny with `spent` when one run remains;
- structure tests compare the tokenizer's site list with a hand-written expectation (conditional and loop sites, the `repeated` mark, assignments, fd numbers, comments, quoted operators, groups) and check that every refused form raises;
- an unbalanced quote denies with the split message; a non-directory `cwd` denies with `unsafe`; the command text appears in no file the test can read afterwards; a merge command writes the same merge pin a `check` call writes; the manifest holds the hook in its own group.

`tests/test_afk_commands.py` covers `check --commands-json`: a denied site records nothing; an allowed call counts one action and writes one pin per merge site; an approval is used by its exact subject once, never by a loop site or a second site; runs are reserved per site and checked before any is kept; redirect targets are floored and, in `strict`, path-checked; `open` judges only the floor and the guards; assignments stay on their site; invalid input is `unknown`; `--argv-json` is unchanged.

`tests/test_afk_hook_oracle.py` is the oracle (macOS only, skipped elsewhere): each accepted corpus entry runs under `/bin/bash` (3.2), a Homebrew bash when installed and `/bin/zsh`, with `--noprofile --norc` or `-f`, through `sandbox-exec` with writes allowed only inside a fresh temporary folder and network denied, under `env -i` with `PATH` holding only recording stubs and a 5-second limit; the tokenizer's sites and the output files and input pipes it names must equal what each shell ran and opened, and the refused entries must raise without running.
