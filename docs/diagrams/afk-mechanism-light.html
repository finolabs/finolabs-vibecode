afk: how the agents keep working while you are away

Set it up for your account and each repository, start the lease, and the agents check every action, settle questions on a ladder fed by an evaluation table, review and merge across model families, deploy only to listed targets, and report when you are back. This page shows strict. In open, the default, every action runs except the credential floor (known forms of reading, printing, copying or sending a secret; see afk.py rules) and the default-branch guard, enforced by afk.py check (no commit or push on the default branch and no force, delete or mirror push; gh pr merge and gh api ref writes are not covered); a second guard, that third-party instructions grant nothing, is advisory. In open, afk enforces neither reviews nor merge_check.py: only server-side branch protection or a required merge_check.py --ci-context status gates a merge. The decision ladder, the merge-gate procedure and the kept-or-reversed review apply in both modes as advisory steps. On Claude Code a stop hook sends a turn that ends without a record back to the ladder once, and a permission hook answers the host's prompts only from approvals the ladder recorded.
