## Parallel dispatch

A model family is a pool of agents, not a single seat (owner decision, 2026-11-07). Independent tasks touch disjoint files, need no ordering, and need not land in one commit. Assign each task to its own run and worktree, including several runs of the same family; tasks sharing files or depending on one another run in sequence. Each run has its own ledger start and finish. Enforcer: advisory (agent judgment); `ledger.py` records the runs.

Before assigning k independent tasks, run `python3 -I <this skill folder>/scripts/parallel_slots.py status`. It reads only canonical `host.md` and `ledger.jsonl` through `data_root.py`, with bounded, owner-checked, no-follow reads. A start without a finish is open; `claude`, `claude-session` and `subagent` share the Claude count. `limit`, `open`, `free`, `families` (each family's `open`, optional `cap` and `free`) and `source` are JSON; uncapped family capacity is null. A missing total defaults to 3 with source `default`; a malformed project entry, unsafe or unreadable inputs and invalid family caps print `unknown`. Enforcer: `parallel_slots.py` reports counts, not reservations.

Assign tasks in order using the existing tier, strength overrides, reachability and capability order. Skip a family that is out of quota or at its cap and spill to the next eligible family that fits; never weaken tier or override a user's explicit route to fill slots. Several tasks may use one family. When two families both qualify, prefer spreading to preserve quota: `quota_probe.py status` reports family pools shared by all that family's runs, not a fresh allowance per run (individual model pools and labelled installs still apply). Enforcer: advisory (agent judgment).

Before each start, run `python3 -I <this skill folder>/scripts/parallel_slots.py check --family <claude|codex|antigravity> [--count k]`. Count is a positive integer (at most 64 digits), default 1; requests above capacity report full. It prints one fixed line: `Parallel slots: available` (exit 0), `Parallel slots: full` or `Parallel slots: unknown` (exit 3). `check` tests both the total and optional family cap. Account for assigned runs not yet recorded; reread before dispatch. With the total full, excess tasks wait. With unknown capacity, resolve the unreadable state or ask the user before adding runs. Enforcer: advisory (agent judgment); the script reports only, so concurrent checks cannot reserve slots.

The limit is per project (repository), owner decision 2026-11-08: the user sets `parallel` (1 to 32) and optional `parallel-caps` (any subset of `claude`, `codex`, `antigravity`, each 1 to the total) for a repository through `fnl-setup add delegation`, stored in the repository's own settings file (`settings.json` in `.finolabs/vibecode/` of the main checkout, read only while it matches the digest approved in the data root; `host.md` is never read for it since 0.2.5); a repository without a setting defaults to 3 and nothing counts across repositories, though family quota pools stay shared. `parallel_slots.py` takes the repository from the current directory (or `--repo <path>`), counts only that repository's open dispatches (those whose ledger project name is the repository's) and reports `other_projects` for the rest. Validate with `parallel_slots.py check-config`: JSON `limit`, `caps`, `source` (`project settings` or `default`) and `legacy_limits`; exit 0 for a valid setting, 3 for default or unknown. The old machine-wide `## Limits` lines are ignored. An invalid, unapproved or edited settings file reads as unset (the default); a cap above the total reports unknown. Enforcer: parser in `parallel_slots.py`; honoring caps is advisory (agent judgment).

`ledger.py start` never blocks on capacity. A dispatch older than its hard cap is reported as `stale` by `parallel_slots.py` and not counted (the script enforces that count; its record stays open). Stale open records do not lock the user out; reconcile them through `fnl-status` with evidence before closing them, or follow an explicit user override (advisory, agent judgment). Sizing, worktrees and integration: [dispatch.md](dispatch.md) "Parallel dispatch". Nothing here changes permissions, Delegation mode, review independence or quota fallback rules.
