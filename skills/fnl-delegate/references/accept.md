# Accept

The coordinator runs the command in `fnl-verification` "Accepting someone else's work", using that skill's self-contained `verify_claim.py`, for every delegated grade (advisory, agent judgment). It reruns exactly the brief's listed test commands, checks the scope and reported head, and writes a verification receipt through `record.py` (script-enforced). Read every semantic `no` and `insufficient`; a judge's `yes` never replaces mechanical evidence. Then decide **accepted**, **rework** in the same run with each defect named, or **rejected** and rerouted. The verdict stays with the coordinator (advisory, agent judgment).

`ledger.py finish --outcome accepted --checkout <task checkout>` refuses without a passing receipt for the dispatch checkout's current head (script-enforced). Use `--checkout` at both `start` and `finish` when the task checkout differs from the working directory. For work with nothing to check, `--accept-unverified --reason <text>` is an explicit escape hatch: the finish line records its use and a reason digest, and `summary` counts `accepted_unverified` per agent. It is not the way past a log scan: use it only when the scan truly cannot run or the coordinator checked the finding, and give that reason. Keep the reason text in the coordinator report; no command, path or task text enters the receipt. Other outcomes are unaffected. This gate covers only delegated runs recorded in the ledger; it cannot stop an agent that never uses the ledger, and the coordinator's own work stays under the review gate.
