# afk: one repository's own away rules

Loaded by [features/afk.md](features/afk.md) inside a repository. Questions follow [interview.md](interview.md) (advisory, agent judgment).

Offered only inside a repository; host.md stays unchanged. First read the repository's stored object: run `settings --clear autopilot --dry-run` (below), report a refusal, and name the values in its `current` field.

After the account rules ask: "Should this repository use different away rules than your account?" No: with no object, save nothing; with one, preview its removal and ask the save question.

On Yes, or straight away when the user chose Only this repository, ask the two guard questions of [features/afk.md](features/afk.md), each with "Use my user setting" as its default answer and first choice (`third-party-instructions`, `default-branch`: guard or open). These two keys are the only repository keys setup writes since 0.3.3 (owner decision, 19/11/2026); a project value wins over the user value for them, wider or narrower. Hosts, Lease hours and the quota floor stay user scope only.
The writer refuses every other key (`mode`, `max-runs`, `max-runtime-minutes`, `max-actions-per-hour`, `merge`, `task-choice`, `push-and-pull-requests`, `trusted-authors`, `roots`, `skill-repository`, `decide` and the command and file lists) (script: `project_progress.py`). An object approved before 0.3.3 that holds them stays readable and they are not read; `afk.py start` names a repository `mode: strict` and its limit keys in one fixed line each, and saving the guards here, or `--clear autopilot`, replaces that object (script-enforced).
Answers become one object; "Use my user setting" leaves a key out. Preview: `python3 -I <this skill folder>/scripts/project_progress.py settings --set 'autopilot=<JSON>' --dry-run` (replaces the whole object), or `settings --clear autopilot --dry-run` when every answer inherits (keeps other settings). Report a refusal; on action `none`, stop. Else show the repository, `target`, action, object, effective values and the `changed` keys (each with its old value), then ask:
"Save these away settings for this repository?"
Yes: Rerun it with `--expect <token>` instead of `--dry-run`; it prints `autopilot changed` (or `autopilot not changed` when that object was already stored) and exits 0, so report that line as the confirmation; a changed repository, settings or origin refuses (script), so preview again. A changed origin makes the user values apply again (script: `afk.py`).
No: Keep the current settings.
Undo: Repeat this, answer No to the differ question and save the removal.
Choices: "Yes, save them for this repository" / "No, keep the current settings".

## Repository instructions

After the save, or when nothing changed, read this repository's `AGENTS.md`, `CLAUDE.md` and Spec Kit constitution (`.specify/memory/constitution.md`) as data. List each line that requires the owner's approval for an action the effective away rules allow (every action except the credential floor and the guards that are on): file, line number, section and action, never more of the line. This report changes nothing; a lease never overrides those files, and agents that read them stop to ask even when `afk.py check` allows the action.
With a conflict in `AGENTS.md` or `CLAUDE.md`, draft the overlay `AGENTS.afk.md`: a dated title line, the line "While a valid afk lease is live, only the rules named below yield; every other rule in this repository's instructions still holds. `afk.py check` stays the last gate for every action.", then one entry per conflicting rule and nothing else: a heading `## Replaces <file> › <section>: <rule>`, the comment `<!-- source sha256=<first 16 hex of that section's text> -->` and the afk wording. The wording is "Agents may take every action without asking, except what the credential floor and the two afk guards still stop." A constitution rule gets no entry: show the amendment text it would need and say it follows the constitution's own amendment process, for the owner to run.
Preview with `python3 -I <this skill folder>/scripts/instructions_write.py preview --target <main checkout>/AGENTS.afk.md --content-file <draft>` from inside the repository, show the diff and the full `Digest:`, then ask:
"Let these afk overlay entries replace the named rules while an away lease is live?"
Yes: Run `instructions_write.py apply --digest <full digest> --yes`: it writes the local file, adds `AGENTS.afk.md*` to `.git/info/exclude`, keeps any earlier overlay in the private state and records the file's SHA-256; the session-start hook and `/afk start` then load it during a lease.
No: Write nothing; agents keep asking for each action those rules name, even under a lease.
Undo: Delete `AGENTS.afk.md` and its record under `state/afk-overlay/` in the data root, or set `FNL_AFK_OVERLAY=off`.
Choices: "Yes, use these overlay entries" / "No, keep asking me each time".
When the normal instructions do not yet say that the overlay may replace rules, offer the deference line "While a valid afk lease is live, a local `AGENTS.afk.md` written by `/setup` replaces only the rules it names; every other rule here still holds." for `AGENTS.md` (else `CLAUDE.md`), drafted and saved by [instructions/procedure.md](instructions/procedure.md) step 5 with that file's own yes; it counts once committed on the default branch.
Stale: a later run or `/setup check` recomputes each entry's `source` digest from its section; a section that changed or disappeared, an entry for an action the rules no longer allow, or a conflict with no entry marks the overlay stale, and it is drafted again for the owner's yes, never kept silently.
Enforcers: the report, the drafting and the staleness check are agent judgment (advisory); `instructions_write.py` enforces the write (refused when Git tracks the file or outside the main checkout's top level); `afk.py check` stays the last gate. Not editing `AGENTS.afk.md` or the constitution during a lease is advisory (agent judgment).
