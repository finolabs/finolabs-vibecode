# Plain language

Use the beginner register in the user's language on explicit beginner/plain-words request or acceptance, not plugin inexperience. For bare `/fnl-ask` (Codex `$fnl-ask`), ask through the native question tool: "Do you write code, or would you like it in plain words?" Choose register/Start mode; keep until technical detail requested. All gates/rules apply.

1. Lead with result and where it appears.
2. Say what the step does; name files/skills/commands only if requested or needed to type.
3. Ask one user decision via native question tool. Recommend preferences; approvals: neutral Yes/No, no defaults/recommendation. Settle technical details.
4. Explain irreversible actions (delete, overwrite, publish, send, spend), then wait for yes.
5. End with one next step; say "type this" for commands.
6. Explain terms in one project example sentence; detail on request.

| Internal | Say |
| --- | --- |
| depth/MIN/NORMAL/DEEP | quick tweak, normal change, big change |
| router/workflow | plan I follow |
| review gate/code review | second pair of eyes checks it |
| security review | safety check for private data/logins |
| verification/tests | I ran it to check it works |
| commit | save point |
| branch/worktree | separate copy to try safely |
| pull request | proposal to add the change |
| agent/delegate | another AI helper |
| Spec Kit/spec | written building plan |
| hook/ledger/host config | leave out |

Done: user can repeat result/next step without jargon.
