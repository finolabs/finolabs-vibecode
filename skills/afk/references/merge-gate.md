# Merge gate

`<script>` is `afk.py` from `delegate`, as in `SKILL.md`.

Merge only when all of these hold (advisory (agent judgment) for gathering current evidence and calling the enforcers):

- The user's recorded Merge answer is yes, the PR is own or trusted, and every changed path (checked in the PR's worktree, on its branch) and the real merge argv pass check as Tier 1. The script enforces the setting and supplied classification; author trust and complete path coverage remain advisory (agent judgment).
- `merge_check.py --independent` from the `review-gate` dependency prints `MERGE OK` for the current head, where the families routing would pick for the reviews differ from the author family. Enforcer: `merge_check.py` for that routed condition only; during the lease it also writes a receipt for that number, head and repository, and check answers `merge-unchecked` (Tier 3) for a `gh pr merge` without one younger than 15 minutes (script), so run it right before the merge. It does not prove which family posted each counted marker: verify the reviewer families of the current-head markers from the review runs and park unknown or same-family evidence (advisory (agent judgment)). If the dependency lacks the option, park the merge (advisory (agent judgment)).
- Same-family fallback: only after trying every other family's reviewers and finding each out of quota or unreachable (advisory (agent judgment)), the author's own family may review. Its markers' second line starts with `Reviewer: <family> (same family as the author; no other family reachable)`, and `merge_check.py --independent --fallback-family <family>` must print `MERGE OK`; it refuses without a live lease, positive out-of-quota evidence for every other present family, and a router trigger other than security, permission or privacy (script). When an enforcer script or instruction file changed, each kind needs two same-family approvals at the head from two different models, each marker naming its model as ` model=<name>` right after that line; one model, the same model twice, a REWORK from either, or a missing model name refuses (script). Running two different models is advisory (agent judgment): the script reads only what the markers state. Record it with `log --kind review-fallback --pr <number> --head <full-head-SHA>` for the user's return.
- Hosted checks and local tests of the touched modules are green at that head, the branch is current, and a third rework round, like every other stop after two rounds, went through "Decide" instead of waiting for the user. Enforcer: advisory (agent judgment), with `merge_check.py` enforcing the evidence it checks.
- Execute only the checked command with the full head SHA pinned: `gh pr merge <number> --merge --match-head-commit <full-head-SHA> --repo github.com/OWNER/NAME`. Recheck after any head change. The script requires one full SHA pin; verifying it is the reviewed current head is advisory (agent judgment).
- After a successful merge, run `worktree_sweep.py list` (from the `review-gate` dependency; read-only). Only for the worktree of the pull request just merged, when it is a candidate and this agent or its runs created it, pass each of the two git commands it prints (`git worktree remove -- <path>`, never forced, and `git branch -d -- <branch>`) through check like any action, from the main checkout, and run them only on Tier 1, else park them. First record the merge with `log --kind merge --pr <number> --head <full-head-SHA>`: with Merge yes, removal is Tier 1 only for a linked worktree whose HEAD is a head this lease recorded, never the one holding this install, and `git branch -d` for a branch that is neither current nor default (script). `git worktree remove` also deletes the files git ignores inside that worktree. Log the rest of the list with sizes for the user's return. Enforcers: check for the classification, git for its own refusals (a dirty worktree, an unmerged branch); choosing the worktree and running the commands are advisory (agent judgment).
