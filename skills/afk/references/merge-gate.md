# Merge gate

`<script>` is `afk.py` from `delegate`, as in `SKILL.md`.

A merge is a decision like any other: the decider merges without the user when the user's authority covers it and the evidence below holds. Authority is the lease itself: afk has one mode since 0.3.3, with no Merge answer and no `merge: decide` record; to keep merges for yourself, write a host deny rule for `gh pr merge` (host). A gray case (a round past the rework limit, whether to use the same-family fallback, a review that approves with findings) goes up "Decide"; its answer chooses what to do next and never replaces `MERGE OK`. A pull request that changes the lease, setup, hooks or instruction files merges like any other when the gate holds (owner decision 4, 18/11/2026).

Merge only when all of these hold (advisory (agent judgment) for gathering current evidence and calling the enforcers). `check` allows every `gh pr merge` ([rules.md](rules.md)); this procedure still applies, so a merge never skips its posted reviews:

- The PR is own or trusted, and every changed path (checked in the PR's worktree, on its branch) and the real merge argv pass check as Tier 1. The script enforces the classification it is given (floor and guards); author trust and complete path coverage remain advisory (agent judgment).
- `merge_check.py --independent` from the `review-gate` dependency prints `MERGE OK` for the current head, where the families routing would pick for the reviews differ from the author family. Enforcer: `merge_check.py` for that routed condition only (script); `check` does not read its result, so run it right before the merge (advisory (agent judgment)). It does not prove which family posted each counted marker: verify the reviewer families of the current-head markers from the review runs and park unknown or same-family evidence (advisory (agent judgment)). If the dependency lacks the option, park the merge (advisory (agent judgment)).
- Same-family fallback: only after trying every other family's reviewers and finding each out of quota or unreachable (advisory (agent judgment)), the author's own family may review. Its markers' second line starts with `Reviewer: <family> (same family as the author; no other family reachable)`, and `merge_check.py --independent --fallback-family <family>` must print `MERGE OK`. Under a live lease it needs only the lease, the author's family and that line on each kind, or a marker of a kind whose configured review role names another family; no quota evidence, router trigger or two-model condition applies (script). Record it with `log --kind review-fallback --pr <number> --head <full-head-SHA>` for the user's return.
- Hosted checks and local tests of the touched modules are green at that head, the branch is current, and a round past the recorded rework limit, like every other stop at that limit, went through "Decide" instead of waiting for the user. Enforcer: advisory (agent judgment), with `merge_check.py` enforcing the evidence it checks.
- Execute only the checked command with the full head SHA pinned: `gh pr merge <number> --merge --match-head-commit <full-head-SHA> --repo github.com/OWNER/NAME`. Recheck after any head change. The script requires one full SHA pin; verifying it is the reviewed current head is advisory (agent judgment).
- After a successful merge, run `worktree_sweep.py list` (from the `review-gate` dependency; read-only). Only for the worktree of the pull request just merged, when it is a candidate and this agent or its runs created it, pass each of the two git commands it prints (`git worktree remove -- <path>`, never forced, and `git branch -d -- <branch>`) through check like any action, from the main checkout, and run them only on Tier 1, else park them. First record the merge with `log --kind merge --pr <number> --head <full-head-SHA>`, which needs the pin an allowed `gh pr merge ... --match-head-commit` check of this lease recorded for that number and head (script). Never remove the worktree holding this install, the current one or the main checkout, and never delete the current or default branch (advisory (agent judgment)). `git worktree remove` also deletes the files git ignores inside that worktree. Log the rest of the list with sizes for the user's return. `ledger.py`'s background worktree cleanup claims nothing while a lease is live (a worktree it claimed just before the lease started is still removed), so these commands are the only removal started under a lease. Enforcers: check for the classification, git for its own refusals (a dirty worktree, an unmerged branch); choosing the worktree and running the commands are advisory (agent judgment).
