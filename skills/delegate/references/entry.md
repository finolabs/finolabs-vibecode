# Delegate entry

You are the **coordinator**, whichever agent you run in: Claude Code, Codex or Antigravity. Agents implement; you grade, route, brief, watch, verify and accept. An agent's report is a claim; the diff and the test output are the evidence.

Before the first dispatch in a session, read the **host config**: `host.md` under the data root resolved by [scripts/data_root.py](../scripts/data_root.py) (`~/.finolabs/vibecode/` by default, relocated only through `fnl-setup`); `ORCHESTRATION_HOST_CONFIG` may supply non-consent settings, but opt-ins and Routing always come from the resolved root. It holds this machine's commands, allowed models, which delegates this coordinator can reach, the judge choice, the heavy-job limits, briefs folder; the parallel limit is per project, in the repository's own settings file. If it is missing, copy [references/host-template.md](host-template.md) and ask the user for the facts you cannot look up. During a live away lease, every question you would ask the user goes to `fnl-autopilot` "Decide" instead (advisory, agent judgment; on Claude Code the away question gate denies the question tool). Project rules (`AGENTS.md`, `CLAUDE.md`, a constitution) win over this skill wherever they conflict.

References carry the detail. For routing: [references/models.md](models.md) maps each agent's models to tiers and strengths, and the Route section below defines the judge fallback. For dispatch: [references/agents.md](agents.md) gives each agent's dispatch contract, including what each one may run, [references/dispatch.md](dispatch.md) the procedures only some runs reach (quota fallback, parallel runs, the heavy-job lock, handover, file placement), and [references/ledger.md](ledger.md) the ledger commands.

For a spec run as a coordinator with one app session per task, load [references/coordinator-sessions.md](coordinator-sessions.md). It covers ownership, standby sessions, checkout handovers and the review gate per user story.

**Advisory (agent judgment):** When the coordinator starts work on a task in a session the user started by hand, run `python3 -I <this skill folder>/scripts/record.py task --id <id>`; the script validates the task id.
