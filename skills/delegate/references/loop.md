# Delegation loop

Run this loop for every delegated task. Each step ends on its criterion.

1. **Grade** the task: kind and difficulty (below). Done when both are named.
2. **Route** it to an agent and model (below). Done when you can state the choice and its reason in one line.
3. **Brief** it with the `handoff` template, saved as "Where files go" says. Without `handoff`, use its headings: Task, Checkout, Context, Relevant files, Current state, What was tried, Acceptance criteria, Tests to run, Constraints, Budget, Report. Done when an agent with zero context could finish the task from the brief alone.
4. **Dispatch** it with a hard time cap, as the runner command itself in the host's background mode (never `( … ) &`, `nohup` or `disown`; one runner per background call), named by its runner and what it does (`session-hygiene` "Titles": `<runner>: <project> <scope> <activity>`) in the host's name field and the log file names, and record it in the ledger. `ledger.py start` builds that label from its own fields and prints it on stderr as `label: <label>` (script); copy the text after `label: ` verbatim (for example `codex sol: demo PR 7 code review`) into the host's name field, which on Claude Code is the `description` of the background Bash or Agent call, whatever the tool's own wording asks for (advisory, agent judgment). The ledger `--task` holds only scope and activity, because project, agent and model are its own fields. The runner is the family plus its short model name (`codex sol`, `agy flash`, `claude sonnet`), never the family alone, so a task list or process view shows which model runs; the same label goes in the task description you give the host and in the wrapper script and log names (advisory, agent judgment: no hook renames a task or a process). Start the command with `FNL_DISPATCH_ID=<ledger id>`, the id `ledger.py start` printed (a host config written before this variable existed lacks it), so the usage metrics can tell the run from a session the user started. Done when the process is running and the ledger has its `start` line.
5. **Watch** liveness at the check deadline from artifacts. Done when the run has ended or been stopped. An Antigravity compaction stop ends a delegated headless `agy -p` run with `status: ERROR` and the fixed message "The conversation is large. Run /compact, or start a fresh session with a short handover, then continue.", which the coordinator treats as "context limit", not a model failure.
6. **Accept**: run `scripts/log_scan.py scan <log>`, read it only with `show <log>`, then accept after verifying the diff and the tests yourself. Get the receipt `finish` needs as [accept.md](accept.md) says: `checks`' `checks.py run --dispatch <id>` in the task checkout when the repository has an approved check list, else `verify_claim.py` over the brief's tests; `--accept-unverified` only for work with nothing to check. Done when the work is accepted, sent back for rework, or rejected.
7. **Record** with `ledger.py finish <id> --log-path <log>`; the descriptor-checked scan runs before any run record or warning. Record the outcome in the ledger. A dispatch sent back for rework stays open; it gets one `finish` line when it is finally accepted, rejected or stopped, with `--rework-rounds <n>`. Done when the dispatch has its `finish` line.

Report a leak by name, never chase it (advisory, agent judgment): tell the user only validated variable names
and that provider/model copies cannot be undone. Redact local logs with `log_scan.py redact <log>`;
apply with `log_scan.py redact <log> --yes --digest <preview digest>` after the run closes and 60 seconds pass. Report transcript
stores for the owner to clean; never touch them or look for a credential's source. Rotation belongs to the owner.
Report: protection is environment-only; HOME credential files remain reachable, and interactive, desktop-app
sessions and in-session subagents are not covered. Private HOME remains an open owner decision.
