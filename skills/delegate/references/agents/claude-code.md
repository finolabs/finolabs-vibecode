# Claude Code

How Claude Code is dispatched as a delegate, what ends its run, and how its result maps to a ledger outcome. Read [agents.md](../agents.md) first: its common procedure (brief lint, private log folder, `delegate_env.py`, hard-cap wrapper, residual risk) holds for every family.

- **Headless**: `python3 -I <this skill folder>/scripts/delegate_env.py --family claude -- claude -p "$(cat "$B")" --model <full model id> --effort <level> --output-format json`, run in the worktree. Headless runs start in a mode that denies anything needing approval: grant what the brief needs with `--allowedTools` (or `--permission-mode acceptEdits` for edit-only work), and cap spend with `--max-budget-usd` and `--max-turns`.
- **Read-only work** (review, advice): `--permission-mode plan`, or `--allowedTools` limited to read and search tools.
- **End of run**: exit status plus the JSON `result`. Check `permission_denials` in the output: a run that hit denials may report success without doing the work.
- **Desktop app sessions**: where the app's session tools exist, start a session with the brief as its first message, in its own worktree when it runs beside other writers (serial spec task sessions share the implementation checkout, as [coordinator-sessions.md](../coordinator-sessions.md) says), and a title in the `tidy` format naming the task. The app refuses to start sessions on turns an automated event or another session began; before an unattended stretch, start the sessions you will need as standby and release each with a message carrying its base commit.
- **Waking coordinators for afk** (`afk` `references/start.md`): on the desktop app, list the sessions with the app's session tools and read from each only whether it is archived, whether another session started it, its working folder, its title and when it was last active; send the fixed message with the app's message tool to the one chosen session per repository. Load the tools through tool search when they are deferred, and read the field names from their schema: they were not verified against a release when this was written. Each call may ask the user to approve it unless the permission mode decides. The CLI and headless runs have no such tools: print the message for the user instead.
- **Declared Claude Code commands** (`## Assignment matrix` lines named `claude<suffix>`): the command replaces `claude` in the headless form. A program on `PATH` runs behind `delegate_env.py` like `claude`. A shell function (for example `claudework`, defined in the user's `~/.zshrc`) is not a program, so start it through the user's own zsh behind the same filter: `FNL_DISPATCH_ID=<id> python3 -I <this skill folder>/scripts/delegate_env.py --family claude -- /bin/zsh -ic 'claudework "$@"' claudework <the headless arguments>`. Only the allowlisted environment and the approved `Delegate environment` names reach the zsh process, so a name the user declined or withdrew stays out; the user's own startup file then runs and whatever it exports, including what the function sets, is the user's own configuration. Check the function with `whence -w <name>` in the user's shell before the first dispatch (advisory).
- A Claude Code delegate owns its task end to end: it may delegate further itself, but it verifies and commits its own work and reports base and new commit SHAs.
