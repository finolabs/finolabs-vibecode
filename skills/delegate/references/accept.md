# Accept

`ledger.py finish --outcome accepted --checkout <task checkout>` refuses without a passing verification receipt for the dispatch's checkout and its current head (script-enforced). Use `--checkout` at both `start` and `finish` when the task checkout differs from the working directory. Two commands write that receipt; pick by what the repository has (advisory, agent judgment):

1. **The repository has an approved check list** (`/fnl-setup add checks`; `checks.py show` prints it): in the task checkout at the run's reported head, with a clean tree, run `checks`' `checks.py run --dispatch <dispatch id>`. It runs the whole list, and only a full pass on a clean tree whose head and list did not move writes the receipt for that checkout and head (script-enforced); a failed, dirty or moved run removes any earlier receipt for the dispatch and writes none. It works whether or not the repository's local-receipt mode is on and never writes the merge gate's local receipt unless that mode is on. Then, when the brief names tests or criteria the list does not cover, also run `verify_claim.py` as below, or check them yourself and say so in the report.
2. **No approved list, or the brief's own tests are the evidence**: run the command in `checks` "Accepting someone else's work", using that skill's self-contained `verify_claim.py`. It reruns exactly the brief's listed test commands, checks the scope and reported head, and writes the receipt through `record.py` (script-enforced). Read every semantic `no` and `insufficient`; a judge's `yes` never replaces mechanical evidence. When the brief lists no runnable test, run what tests cover the change yourself, and say in the coordinator report which ran and why there was no list.

The latest of these runs for a dispatch decides: each replaces the dispatch's receipt. Then decide **accepted**, **rework** in the same run with each defect named, or **rejected** and rerouted. The verdict stays with the coordinator (advisory, agent judgment).

`--accept-unverified --reason <text>` is for work with nothing to check: a review, advice, a document-only change with no test, or a checkout the checks cannot run in. It is not the way past a failing or skipped check, a dirty tree, a missing list you could have run the brief's tests instead of, or a log scan: use it only when the scan truly cannot run or the coordinator checked the finding, and give that reason. The finish line records its use and a reason digest, and `summary` counts `accepted_unverified` per agent, so the receipt-backed share is `accepted` minus that count. Keep the reason text in the coordinator report; no command, path or task text enters the receipt. Other outcomes are unaffected. This gate covers only delegated runs recorded in the ledger; it cannot stop an agent that never uses the ledger, and the coordinator's own work stays under the review gate.
