# Ledger

Record every dispatch with `scripts/ledger.py` in this skill's base directory. It appends to `ledger.jsonl` under the resolved data root, ignoring environment overrides. The ledger measures whether this routing works, so write each line at the moment it happens:

```bash
L="<this skill's base directory>/scripts/ledger.py"
python3 -I "$L" start --project demo-app --task "003 T101" \
  --kind implement --grade medium --coordinator claude --agent codex \
  --model gpt-6.1-sol --route-by table --budget 45
python3 -I "$L" finish <id> --outcome accepted --rework-rounds 1 --tests passed
python3 -I "$L" open                     # dispatches with no finish line
python3 -I "$L" stale                    # preview this repository's open records past 2x budget and 24 hours
python3 -I "$L" stale --close --digest <first 12+ hex digits>
python3 -I "$L" summary --since 2026-11-01
python3 -I "$L" summary --json           # the same rows as JSON, with quota and error counts
```

## Start

- **Project label**: one short, stable `--project` label per repository, used from every worktree of it; never a customer, personal or machine name. Use the repository's `ledger` project setting (else the folder name): the dashboard joins dispatches by that name, not by the display label, and a different label joins nothing until `/setup add project` records it as the repository's `ledger` entry.
- **Task label**: `--task` holds only scope and activity, short names, no task data, secrets or personal data. For task progress use `<feature> T<id>` with the exact three-digit feature number (for example `003 T012`); multiple ids or ranges of at most 20 ids link each task, and a label without a feature stays unlinked.
- **Agent**: `--agent claude-session` for a Claude Code app or interactive session, `claude` for a headless `claude -p` run, `subagent` for an in-session subagent; `--install <name>` names an extra Claude Code command such as `claudework` (the names the assignment matrix accepts).
- **Grade and type**: `--grade` is one of `easy`, `medium`, `hard`, `very-hard` and `ultra-hard` (`SKILL.md` "Grade"). Optional `--work-type <type>` (`frontend`, `design`, `video`, `three-d`, `image-generation`, `transcription`) and `--level <1-5>` run the same query as `route_pick.py pick` and record `pick_rank` (the chosen install or agent and model's position among the survivors, 0 outside them); stderr then says `off the preferred order: rank <n>` or `off the preferred set: <reason>`. It never refuses the dispatch.
- **Why this route**: `--reason fallback-quota` for a quota fallback, `--reason fallback-failure` for a reroute after a failed run, `--reason user-choice --route-by user` for a route the user named, and `--route-by judge` when a validated configured-judge response informed it.
- **Delegation mode `manual`**: `start` refuses a cross-family record without `--route-by user`, writes nothing and exits 1 (Claude, `claude-session` and `subagent` are one family). It blocks the record, not the dispatch; an unavailable or invalid mode changes nothing.
- `start` prints the dispatch id on stdout and the run's name on stderr (`label: <runner>: <project> <task>`, the runner being family plus short model name, such as `codex sol`). It warns, and still records, when the model is not one the assignment matrix lists or `--project` differs from the repository's `ledger` entry. It records `coord_session`: the first 12 hex characters of the SHA-256 of the `CLAUDE_CODE_SESSION_ID` environment value, never the raw id and never from a command-line option (an argument would show in process listings and parser errors), `null` when the variable is unset; a predictable id can be guessed from its hash, so treat the ledger as private.

## Finish

- **Receipt before acceptance**: before `finish --outcome accepted`, get the receipt as [accept.md](accept.md) says: `checks`' `checks.py run --dispatch <id>` in the task checkout when the repository has an approved check list, else the self-contained `verify_claim.py` from `checks` "Accepting someone else's work", and read its evidence. Pass `--checkout <task checkout>` to both `start` and `finish` when the task runs elsewhere; the gate requires a passing receipt for that checkout's current head. For work with nothing to check, use `--accept-unverified --reason <text>` and keep the full reason in the coordinator report: the ledger stores only its digest and counts the exception in `summary`.
- **Head**: for review routing, add `--head <implementation head SHA>` (forty lowercase hex characters) to `finish`; it copies the agent from the start record, and only a record with a head establishes authorship (commit trailers alone are insufficient). With a verification receipt, this head must match the verified head. On a `review` dispatch, `--head` records `reviewed_head`, which never binds authorship.
- **Review dispatch**: accepted on its posted review with `finish <id> --outcome accepted --head <reviewed head> --review-url <comment URL>`, with no receipt and no `--accept-unverified`. The URL must match `https://github.com/<owner>/<repo>/pull/<n>#issuecomment-<id>`; it is checked by pattern, never fetched or stored, and records `review_posted: true`. Every other kind keeps the receipt rule. `--reason <text>` may go with any outcome; only its digest is stored.
- **Field checks**: `finish` refuses, writing nothing, a negative `--rework-rounds`, more rework rounds than the loop's limit (`Rework limit` under `## Reviews` of the host config, 2 to 4, default 2) without a `--reason`, and `--outcome accepted` with `--tests failed`. Use `finish --retro` for a record written after the fact; its duration stays out of the medians.
- **Log scan**: `--log-path <log>` must lie directly inside the private `.finolabs/logs/` folder of the current, the `--checkout` or the main checkout; `finish` scans it and stores only `log_scan: no_findings|findings|not_scanned` (an empty log is `not_scanned`). Any other location, a link or another user's file is refused and nothing is recorded; omit the path to record `not_scanned`. The `--head` and receipt gates still apply.

## Open and ended runs

- **Ended line**: when `delegate_env.py` runs a dispatch with `FNL_DISPATCH_ID` set to its ledger id, it appends an `ended` line with the child's exit code after the child exits, holding no command text, output or path (script-enforced; a failed write is silent and never changes the exit status). It is not a finish: `open` shows `ended exit=<n>` beside the record, `stale` treats it as due after 24 hours (or `--older-than-hours`) and proposes `error` for a nonzero exit or `cancelled` for exit 0, and `summary` ignores it.
- **Open-run reminder**: on Claude Code a `UserPromptSubmit` hook (`scripts/open_dispatch_nudge.py`) prints one fixed line, at most once per 30 minutes per session, naming up to five runs this session started that have no `finish` line and either ended or passed their budget (60 minutes when absent). It only prints and never denies, reads only the ledger and its own throttle mark, and `FNL_DISPATCH_NUDGE=off` disables it. Recording the outcome stays agent judgment (advisory); Codex and Antigravity are not covered.

## Stale records

`stale` previews only this repository's open records (the ledger project `status` resolves for the current checkout: its `ledger` project setting, else the checkout folder name) and refuses when none resolves. By default it lists records past twice their budget and at least 24 hours old (24 hours without a usable budget); `--older-than-hours <n>` (1 to 8760) sets another threshold, but a record inside its budget is never listed. Each line shows id, age against budget, label and, without reading log content, whether `<id>.log` exists in this checkout's private `.finolabs/logs/` folder, its age and its `exit=<code>` line. The proposed outcome is `error` for a nonzero exit, `stalled` for exit 0 or no exit line, `cancelled` with no log; a symlinked, hard-linked or foreign log leaves its record open.

The preview writes nothing to the ledger and prints a digest valid for 60 minutes. Show the list to the user and, after their yes, run `stale --close --digest <first 12+ hex digits>`: it appends one `finish` line per previewed record still open and still past the threshold, noted as closed late with `log_scan: not_scanned`. Lines are only appended, under the `finish` lock; none is deleted, and `open`, `summary` and the session-start open count read a closing line like any `finish`. A mismatched, expired or missing preview, a changed data root or a changed scope writes nothing. `--all-projects` widens the preview with a warning that other projects' runs cannot be judged from here, and closes only with `stale --close --all-projects --digest <digest>`; a one-project preview closes only from a checkout of that project. It never marks a record `accepted` and never touches receipts. Enforcer: the digest check in `ledger.py`; asking the user before closing is agent judgment (advisory).

## Summary

`summary` reports, per agent, model, kind and grade, the first-pass acceptance rate, timeouts and stalls, fallbacks, median duration, unverified acceptances and the quota, error and cancelled counts; `--json` adds `closed_late`, `retro`, `accepted_findings` and `review_unposted`. A `cancelled` record closed late (its note starts with `closed late by ledger stale` or `closed late by the coordinator`; use the second when you close one by hand) gives no verdict on the run, so it is shown as a separate total, outside the rates and medians. With `pick_rank` records, it adds per install or agent the shares at rank 1, at a lower rank and outside the set. Below the table it flags accepted runs whose log scan had findings and review acceptances recorded without `--review-url`.
