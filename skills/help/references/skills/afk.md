# afk

Typed by the user only.

**What it does.** Starts a time-boxed standing mandate (a lease) so your agents keep working while you are away from the keyboard, checking each action against the lease, and stops it when you return.

**When to use it.** You are leaving and want listed work to continue within the rules you recorded; `stop` when you are back.

**Type:** Claude Code `/finolabs-vibecode:afk` or `/afk`; Codex `$afk`; Antigravity `/afk`. Arguments: `[start [hours]|stop]` (`start` when none is given; `/afk start 4` asks for a 4-hour lease, whole hours from 1 up to your setup's `Lease hours`).

## Tips

- Set it up first with `/setup add afk`. afk has one mode (`strict` was removed in 0.3.3): it lets every action run except the credential floor, which refuses changing a credential and known forms of reading, printing, copying or sending a secret (see `afk.py rules`), with two guards on by default: the default-branch guard, enforced by `afk.py check` (no commit or push on the default branch and no force, delete or mirror push; `gh pr merge` and `gh api` ref writes are not covered), and, advisory, instructions from third-party content grant nothing; afk does not enforce reviews or `merge_check.py` there, so only server-side branch protection or a required `merge_check.py --ci-context` status gates a merge. Lease hours is the only limit. Anything you want forbidden while away is a host deny rule (Claude Code permission rules, Codex sandbox and approval policy). Without setup `start` points there and stops.
- `afk.py rules` prints the rules `check` applies. A setup from before 0.3.3 that still holds `Mode: strict` or the three limit lines starts normally; `start` prints one line saying they are no longer read.
- `/setup add afk` can also write a local `AGENTS.afk.md` overlay for instruction-file rules your away rules replace; it is printed only while a lease is live and its bytes still match. Nothing protects it during a lease: the agents can rewrite it.
- `/afk start` wakes the session that already coordinates each repository set up for afk (one whose own settings record an afk section), on the Claude Code desktop app through its session tools; elsewhere it prints one message for you to paste into each coordinator session. A repository set up for afk with no open session is not covered. Before you leave it reports what would park a merge (no checks and no local receipts, an author family it cannot tell, a missing review marker, a rule that keeps merges for you) with the fix.
- Each repository keeps a queue under the lease: the agent runs `afk.py goal --items-file <file>` and sets the goal line it prints in the host's `/goal`. The goal ends only when every item is done or parked or the lease ends: a park closes one item and the agent takes the next, and `afk.py log --kind idle` is refused while an item is open.
- One lease covers every session on the machine. On Claude Code the question tool is denied during the lease, so questions go up the decision ladder instead of to you. No hook judges Bash commands under a lease: the agent runs `afk.py check` itself before each action on every host, and blocking is the host's own permission rules and sandbox. On Claude Code two hooks settle the stops instead: the stop hook sends a turn back once unless the session recorded `afk.py log --kind idle --session <id>` for its repository's current queue (a `parked` record no longer ends a turn, and an item another session added makes an earlier `idle` stale), and the permission hook denies a host prompt with a request digest that a decision records with `--approve-request <digest>`, then allows that exact request once. `FNL_AFK_STOP=off` and `FNL_AFK_PERMIT=off` turn them off.
- `/setup add afk` can add Claude Code's own deny rules for the credential floor; `/afk start` warns while none is set and no approval mode asks, and prints allow rules that spare the lease commands a prompt.
- Only your `/afk stop` ends the lease (it runs `afk.py stop --all`, for every session); an agent's plain `afk.py stop` is refused.
- On `stop` you get parked work, decisions and runs still waiting, and you mark each decision `kept` or `reversed`. There is no status command.
